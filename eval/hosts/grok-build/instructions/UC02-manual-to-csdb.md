# UC02 — 体験型マニュアルを CSDB にする

## 依頼文

> この体験型マニュアル（`fixtures/incoming/kenbaiki.manual.json`）を S1000D のデータモジュールにして、`csdb/` に入れてください。
> 型式識別コード（modelIdentCode）は `KENBAIKI` です。BREX は `csdb/` にあるプロジェクトの BREX（KENBAIKI）を使ってください。
> それ以外の採番は、あなたが決めた試作用の値で構いません。

## 入力

- `fixtures/incoming/kenbaiki.manual.json`（自作の体験型マニュアル。Topic 4 件と用語集）
- `fixtures/incoming/img/`・`fixtures/incoming/cad/`（マニュアルの `assets` が指す素材。中身はダミー）
- `csdb/` の BREX 2 件

## 手順

1. 入力のマニュアルを読み、Topic の数と種類、用語集の有無を書く。
2. 採番の規則（SNS・情報コード・責任企業など）を決め、決めた値と理由を書く。決めた規則は `work/UC02/` に JSON で残す。
3. 書き込まずに変換し、次を表にする: 作られる DM とパブリケーションモジュールの数、それぞれの DMC と検証状態、自動で直された箇所、残った修正、マニュアルの中で S1000D に表せなかったもの。
4. 残った修正があれば、候補の中から選んで片付ける。候補が無いものは、残したまま進むか、採番を変えて手順 3 からやり直すかを決め、理由を書く。
5. 手順 3〜4 の結果を確かめてから、`csdb/` に書き込む。
6. `csdb/` 全体を検証し、書き込んだものがすべて読めるか、検証状態が手順 3 と同じかを確かめる。
7. 変換の報告（Skill があれば Skill の Report の型）を書く。

## 記録すること

- 発火した Skill の名前。Skill を使わずに MCP を直接呼んだ場合はそう書く
- 手順 3 と手順 6 の検証状態の違い（あれば）
- 採番の台帳（どの Topic がどの DMC になったか）

## 成果物

- `csdb/` に書いた DM とパブリケーションモジュール
- `work/UC02/`（採番の規則、台帳）
- `reports/UC02.md`
