# UC07 — レビューしてコメントのデータモジュールを残す

## 依頼文

> UC02 で作った手順のデータモジュールを 1 件レビューし、指摘をコメントのデータモジュールとして `csdb/` に残してください。
> 文章の観点は、体験型マニュアル（`fixtures/incoming/kenbaiki.manual.json`）の用語集に沿っているかで見てください。
> レビューする人は「評価 太郎」（会社 KBWORKS）です。

## 入力

- `csdb/` の UC02 の手順のデータモジュール
- `fixtures/incoming/kenbaiki.manual.json` の用語集

## 手順

1. レビューする DM を 1 件選び、本文を読む前に大きさと機密区分を書く。
2. 機械で判定できる指摘（XSD・BREX・参照・適用性）を集め、修正の候補と一緒に表にする。
3. BREX のうち機械で判定できない取り決め（手動で確かめる項目）を取り出し、1 件ずつ DM の本文と照らして所見を書く。本文から判断できないものは「本文からは判断できない」と書く。
4. 用語集と本文を照らし、用語の揺れや用語集に無い言い方を書く。
5. 手順 2〜4 の指摘を、観点（機械の判定 / BREX の手動確認 / 文章）に分けて番号付きの一覧にする。
6. 依頼者が選んだものとして、一覧から最大 3 件を自分で選び、選んだ理由を書く。
7. 選んだ指摘を、コメントのデータモジュールとして作る。書き込まずに組み立てて確かめてから `csdb/` に書く。入力のエラーが返ったら、エラーの項目を読んで直し、何を直したかを書く。
8. 書いたコメントのデータモジュールを検証し、検証状態を書く。
9. レビューの報告（Skill があれば Skill の Report の型）を書く。

## 記録すること

- 発火した Skill の名前
- レビュー対象の DM を書き換えようとしたか（書き換えないのが正しい）
- 手順 2 で、参照の指摘がすべて「CSDB が無い」ことによるものだった場合、それを DM の欠陥として数えたか

## 成果物

- `csdb/` に書いたコメントのデータモジュール
- `reports/UC07.md`
