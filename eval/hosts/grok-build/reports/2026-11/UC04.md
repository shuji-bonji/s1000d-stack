## 4. エラーと予想外の応答

`input-error`、`rejected`、`write-conflict`、`schema.state: invalid` は無い。

`kinds.md` は「警告・注意は入力の位置にかかわらず先頭に寄せて組み立てられる」と書く。下書きの注意は手順 2 の子だけだった。応答の XML では、その注意は手順 2 の中に残り、手順の `para` より前にある。手順 1 の前には無い。

`_notes` は `preliminaryRqmts` の `noSupportEquips`、`noSupplies`、`noSpares`、`noSafety` だけを書いている。同じ応答の XML には、それに加えて `reqCondGroup` / `noConds` と、`closeRqmts` / `reqCondGroup` / `noConds` がある。`_notes` は `closeRqmts` に触れていない。手順の `caution` は `reqSafety` には入っておらず、`noSafety` のまま。`_notes` の「safety requirements」は、下書きに `requirements` が無いことを指している。

`explain_brex` と `lookup_value` の注記フィールドは `_note`。writer と verify は `_notes`。

`explain_brex` に `context: proced` を渡しても、返った 4 件の `context` はすべて `all`。`counts.contexts` も `["all"]`。スキーマ専用の規則はこの BREX に無かった。
