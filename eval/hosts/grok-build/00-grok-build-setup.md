# 00 — 環境の確認とスモークテスト

Grok Build が S1000D Stack を呼び出せる状態かを確かめる手順です。最初のセッションで、手順 1 から順に行ってください。期待した結果と違っても止めずに、違ったことを記録して次へ進みます。

MCP の登録・Skill の配置・設定ファイルは、依頼者が済ませています。足りないものを自分で入れたり、設定ファイルを書き換えたりしないでください。

## 手順 1 — ホストと版

次を表にしてください。

1. OS、Node.js の版、`npx` の有無
2. 起動している 4 サーバーの `serverInfo`（名前と版）。期待値は次のとおり
   - s1000d-brex-mcp 0.5.0 / s1000d-verify-mcp 0.6.1 / s1000d-reader-mcp 0.7.1 / s1000d-writer-mcp 0.1.2
3. 各サーバーがどの登録から起動したか（plugin か、設定ファイルか）
4. `npm view @shuji-bonji/s1000d-brex-mcp version` など 4 本の結果。plugin は `npx -y …@latest` で起動するので、npx のキャッシュの版と npm の最新版が違うことがある
5. s1000d 系の MCP サーバーが 4 本より多く見えていないか（名前の違う同じツールが 2 組ないか）

## 手順 2 — Skill

発見された Skill のうち、次の 4 つの名前・版・置き場所を表にしてください。期待値はどれも 0.1.1 です。4 つとも GitHub のリポジトリから plugin として入れています。置き場所がリポジトリの複製なら、そのコミット（`git rev-parse --short HEAD` など、読むだけの操作で分かる範囲）も書いてください。

- experience-to-s1000d
- s1000d-publish
- s1000d-review
- s1000d-translate

Skill を読めない場合は、そのことと理由を書いてください。以降の UC は MCP を直接呼んで進め、報告書には「Skill なし（MCP のみ）」と書きます。

## 手順 3 — 設定（S1000D の配布物と CSDB の場所）

4 サーバーは、S1000D の配布物の場所（`specDir`）と CSDB の場所（`csdbDirs`）を、環境変数 `S1000D_SPEC_DIR` / `S1000D_CSDB_DIR` か、設定ファイル `~/.config/s1000d-stack/config.json` から読みます。

1. 設定ファイルの中身を表にしてください（読むだけ。書き換えない）
2. 次の手順 4 の応答から、4 サーバーがそれぞれ `specDir` と `csdbDirs` を認識しているかを判断し、その根拠（応答のどの項目か、`_notes` のどの文か）を書いてください

## 手順 4 — スモークテスト

各サーバーで 1 つずつ、次のことを行ってください。失敗しても次のサーバーへ進み、結果を表にします。どのツールを選んだかも書いてください。

| # | サーバー | 行うこと |
| --- | --- | --- |
| 1 | s1000d-verify | `specDir` にある XSD の版と数を調べる |
| 2 | s1000d-brex | 既定の BREX（S1000D の配布物に入っているもの）の概要を 1 回だけ取る |
| 3 | s1000d-reader | `csdb/` のデータモジュールを一覧にする（期待は BREX の DM 2 件: KBWORKS と KENBAIKI） |
| 4 | s1000d-writer | 書き込まずに、題名「スモーク」と段落 1 つだけの説明のデータモジュールを組み立て、`verification` を見る。`csdb/` には書かない |

## 手順 5 — 検体の一覧

`fixtures/incoming/` と `csdb/` のファイルを、名前・バイト数・md5 の表にしてください。

## 手順 6 — 報告

`reports/SETUP.md` に、手順 1〜5 の結果と、次の一覧を書いてください。

1. このホストでは測れない項目（例: DeepL の MCP が無い）
2. 手順の途中で迷った箇所と、自分で決めたこと

ここで止まり、UC01 には進まないでください。
