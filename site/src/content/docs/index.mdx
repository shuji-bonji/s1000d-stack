## Components

<CardGrid>
  <LinkCard
    title="s1000d-brex-mcp"
    description="Lists the BREX (Business Rules Exchange) you were given by a customer or project as sentences that say what is required of each element. Checks data modules against each layer of the BREX chain (project → organisation → S1000D default BREX) and returns every violation with its location, value, rule ID and severity level."
    href="/s1000d-stack/mcp/brex-mcp/"
  />
  <LinkCard
    title="s1000d-verify-mcp"
    description="Performs validation against the official XSD, the BREX check and broken reference detection together, and returns them as a single verification status. Use it for checks before delivery and as preparation before passing data to the reader."
    href="/s1000d-stack/mcp/verify-mcp/"
  />
  <LinkCard
    title="s1000d-reader-mcp"
    description="Passes data modules to the LLM as a structure of headings, steps, warnings and illustrations. Which product the content applies to (applicability) is evaluated by the server, and only the result is passed on. The LLM sees neither XML nor applicability expressions."
    href="/s1000d-stack/mcp/reader-mcp/"
  />
  <LinkCard
    title="s1000d-writer-mcp"
    description="Creates data modules without letting the LLM write XML. It builds the XML from a structured draft, verifies it, and automatically applies only the fixes that have exactly one candidate. It also converts experiential manuals, creates comment data modules, and hands sentences out and back for translation."
    href="/s1000d-stack/mcp/writer-mcp/"
  />
  <LinkCard
    title="s1000d-core (library)"
    description="A library shared by the four MCP servers for splitting DMCs and ICNs, reading the identification and status section, BREX checks, XSD validation, reference resolution, applicability evaluation and building data modules."
    href="/s1000d-stack/lib/s1000d-core/"
  />
  <LinkCard
    title="Skills (4)"
    description="Procedures that tell Claude which MCP servers to call in which order and what to ask the user at each step. There are four: converting an experiential manual (experience-to-s1000d), creating data modules (s1000d-publish), review (s1000d-review) and translation (s1000d-translate)."
    href="/s1000d-stack/skill/experience-to-s1000d/"
  />
</CardGrid>
