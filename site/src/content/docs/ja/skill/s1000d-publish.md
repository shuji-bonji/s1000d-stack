`s1000d-publish` は、構造化した下書きから S1000D® のデータモジュールを 1 件ずつ作り、検証を通して CSDB に入れる Skill です。体験型マニュアルを経由しない、技術文書の書き手のための手順です。Skill は、どの MCP サーバーをどの順番で呼び、各段階で利用者に何を聞くかを Claude に伝えるもので、組み立てや検証の処理は持ちません。

[GitHub](https://github.com/shuji-bonji/s1000d-publish-skill) / [Release](https://github.com/shuji-bonji/s1000d-publish-skill/releases)

## 何をする Skill か

- **渡すもの**: 材料（文章、メモ、既存のデータモジュール）、出力先の CSDB のフォルダー、機密区分、採番の規則です。データモジュールの種類（説明、手順、プロセス、故障探求）は、利用者と相談して決めます。
- **受け取るもの**: 検証したデータモジュール 1 件、作ったデータモジュールが DML（データ管理リスト）に載っているかの照合結果、Publish Report（検証状態、自動で直した修正、書き込んだファイル）です。書き込みは、利用者が確認した後に行います。

## 前提の MCP サーバー

| MCP サーバー | 必須・任意 | 最低版 | 役割 |
| --- | --- | --- | --- |
| [s1000d-writer-mcp](/s1000d-stack/ja/mcp/writer-mcp/) | 必須 | 0.1.1 | 下書きからデータモジュールを組み立てて検証し（`build_data_module`）、選んだ修正を適用します（`apply_fixes`） |
| [s1000d-verify-mcp](/s1000d-stack/ja/mcp/verify-mcp/) | 必須 | 0.6.0 | 書いたデータモジュールを検証し（`verify_data_module`）、DML と照合します（`reconcile_dml`） |
| [s1000d-brex-mcp](/s1000d-stack/ja/mcp/brex-mcp/) | 任意 | 0.4.0 | プロジェクトの BREX の決まりを、書き手向けに説明します（`explain_brex`） |
| [s1000d-reader-mcp](/s1000d-stack/ja/mcp/reader-mcp/) | 任意 | 0.7.0 | 既存のデータモジュールを読んで、書き直しの元にします（`read_data_module`） |

必須のサーバーが接続されていないとき、Skill は作業を始めず、接続の方法を伝えて止まります。任意のサーバーが接続されていないときは、報告の該当項目に「未実施（ツール未接続）」と書きます。

## 手順の流れ

```mermaid
flowchart LR
  A["材料と種類を<br/>利用者と決める"] --> B["プロジェクトの BREX の<br/>決まりを要約する"]
  B --> C["下書きを作り<br/>利用者が確認する"]
  C --> D["書き込まずに<br/>組み立てて検証する"]
  D --> E["残った修正を<br/>利用者が選ぶ"]
  E --> F["確認後に書き込み<br/>検証する"]
  F --> G["DML と照合する"]
  G --> H["Publish Report"]
```

1. 材料、新規か書き直しか、出力先の CSDB のフォルダー、機密区分を確かめ、データモジュールの種類を利用者と決めます。
2. brex サーバーが接続されていれば、プロジェクトの BREX の決まりを、書き手向けに要約します。応答にない決まりは足しません。
3. 採番の規則を聞きます。情報コードの既定はないので、プロジェクトが登録したコードを聞きます。
4. 題名・段落・手順・警告・表・参照だけからなる下書きを作り、利用者に見せて確認してもらいます。DMC や BREX の参照は書きません。
5. 書き込まずに組み立てて検証します。残った修正のうち、候補が複数あるものは利用者が選び、候補がないものは利用者に聞きます。
6. 利用者が書き込み先を確認してから書き込み、書いたデータモジュールを検証します。
7. DML と照合し、作ったデータモジュールが DML に載っているかを報告します。載っていないときは、利用者に伝えます。
8. 作った結果と検証状態を Publish Report にまとめます。

## Skill がしないこと

- XML を書きません。書くのは下書きだけで、XML は writer サーバーが組み立てます。
- 情報コード、機密区分、適用性を、利用者に聞かずに決めません。
- 候補の外の値で修正しません。
- BREX の決まりを、サーバーの応答にない内容で説明しません。
- DML を作ったり更新したりしません。writer サーバーにその機能がまだないので、載っていないときは、利用者のツールで追記してもらいます。
- `schema-not-found` と `not-run` を合格とは書きません。S1000D への準拠は判定しません。

## 入れ方

Claude Code では、次のコマンドで入れます。

```text
/plugin install s1000d-publish@shuji-bonji
```

必須の MCP サーバーは、Skill の `plugin.json` に依存として宣言してあります。MCP サーバーの設定（`S1000D_SPEC_DIR` など）は[導入手順](/s1000d-stack/ja/guide/getting-started/)にあります。
